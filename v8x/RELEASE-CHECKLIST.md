# V8X Lead → Demo Release Checklist

## Lead gate
- Fail-closed dedupe before deep research.
- Reserve identity as soon as serious research starts.
- Confirm active custom-kitchen business.
- Confirm attributable authentic imagery.
- Confirm website/commercial gap using current evidence.
- Verify public route; direct WhatsApp only when exact number is verified.
- Separate FACT / INFERENCE / UNKNOWN.
- OUTREACH_READY and OFFER_READY are separate decisions.

## Demo gate
- Prospect-specific data only.
- No stock or AI imagery.
- No previous prospect names, phone numbers, marks, initials, copy or assets.
- Arabic-first RTL.
- Real interactive 3D only when it materially supports the pre-sales decision.
- Preserve state and produce a concise designer-ready brief.
- No false CAD / quote / manufacturing claims.
- Mobile-first; validate 390 / 430 / 1440 before release.
- HTTP 200 + correct title + correct identity + correct contact route.

## Deployment discipline
- Draft work stays on the `v8x` branch.
- Preview deployments are disabled.
- Only an approved release is copied to `main/v8x/**`.
- V7X ignores V8X-only release commits.
- V8X ignores commits where its root folder did not change.
- One approved demo release should create one production deployment.
- Give each prospect a unique alias; never recycle another prospect's client URL.
